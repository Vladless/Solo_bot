# PayHOT

Интеграция использует [PayHOT API v2](https://docs.pay.hot/overview) и поддерживает
карты, СБП и SberPay в рублях. Каждый способ отдельно включается в группе PayHOT
в настройках касс. По умолчанию все три способа выключены.

## Настройка

Создайте рабочий API-ключ с правами «Платежи». Заполните переменные в конце `settings/config.py`:

```python
PAYHOT_API_KEY = ""  # Рабочий API-ключ PayHOT с правами «Платежи».
PAYHOT_WEBHOOK_SECRET = ""  # Полный Webhook signing secret, включая префикс.
```

Эти значения также можно передать переменными окружения процесса бота: окружение
имеет приоритет. Для Docker используйте смонтированный `settings/config.py` либо
явно передайте переменные в контейнер. После изменения ключей перезапустите бот.

В кабинете PayHOT откройте проект → Webhook и добавьте endpoint:

```text
https://<домен-бота>/payhot/webhook
```

Выберите события `payment.succeeded`, `payment.failed`, `payment.cancelled`,
`payment.captured`, `payment.refunded` и `payment.manual_reconciliation`. Адрес
должен вести на веб-сервер бота и принимать POST без перенаправления. Секрет
этого endpoint задаётся в `PAYHOT_WEBHOOK_SECRET`; API-ключ его не заменяет.
HTTPS-адрес возврата после оплаты настраивается в проекте PayHOT. API создания
платежа не принимает `success_url` и `failure_url`, поэтому переданные сайтом
адреса возврата этот провайдер не использует.

Затем включите нужные способы в настройках касс. Начальные значения `PAYHOT_CARDS`,
`PAYHOT_SBP` и `PAYHOT_SBERPAY` заданы в конце `settings/config.py`; сохранённые
настройки касс имеют приоритет:

| Идентификатор | Способ в API | Валюта |
| --- | --- | --- |
| `PAYHOT_CARDS` | `card` | RUB |
| `PAYHOT_SBP` | `sbp` | RUB |
| `PAYHOT_SBERPAY` | `sberpay` | RUB |

Соответствующие методы должны быть подключены к кассе PayHOT. Они доступны для
пополнения баланса, быстрой оплаты покупки и оплаты на сайте. Если новый поток
оплаты уже включён через `USE_NEW_PAYMENT_FLOW`, включённые способы PayHOT
добавляются в него автоматически.

Для SberPay клиент указывает свой номер, привязанный к Сбербанку. Интеграция
использует режим push/SMS (`back2app`) и передаёт номер в формате `+7XXXXXXXXXX`.
Номер фиксируется только в сохранённом запросе конкретной попытки оплаты, чтобы
повтор запроса сохранял те же условия; в журнал он не выводится.

## Дополнительные настройки

```python
PAYHOT_PREVIOUS_WEBHOOK_SECRET = ""  # Предыдущий секрет на время ротации; затем удалить.
PAYHOT_API_BASE_URL = "https://app.pay.hot/api/v2"  # Базовый адрес рабочего API.
PAYHOT_WEBHOOK_PATH = "/payhot/webhook"  # Путь приёма POST-уведомлений.
PAYHOT_REQUEST_TIMEOUT = 25  # Максимальное время одного запроса API в секундах.
PAYHOT_MIN_AMOUNT_RUB = "0.01"  # Локальный нижний предел суммы пополнения.
PAYHOT_MAX_AMOUNT_RUB = "1000000.00"  # Локальный верхний предел суммы пополнения.
```

Реальные пределы определяются подключённым способом, валютой и комиссией PayHOT.
При отклонении суммы API возвращает допустимый диапазон, который бот показывает
пользователю. Суммы с более чем двумя знаками после запятой не округляются.
Все клиентские тексты PayHOT находятся в общем `settings/texts.py`
в переменных `PAYHOT_*`.

## Обработка платежей

Счёт сохраняется до обращения к кассе вместе с каноническим владельцем и снимком
корзины. Номер вида `payhot_<uuid>` одновременно служит `merchant_order_reference`
и ключом идемпотентности. При временной ошибке создания повторяется тот же запрос.
Если повтор возвращает платёж без ссылки, интеграция перевыпускает Checkout.
Готовая `checkout.url` передаётся целиком вместе с фрагментом `#token`; ссылка
и токен не записываются в журнал или метаданные счёта.

Обработчик проверяет HMAC-SHA256 исходных байтов, время доставки с допуском
пять минут, затем сверяет номер счёта, ID платежа, сумму, валюту и способ оплаты
с сохранёнными данными и текущим ответом API. Зачисление выполняет общий
платёжный процесс с блокировкой счёта. Повторные события не зачисляют средства
повторно; старое событие ошибки не отменяет подтверждённую оплату. Проверка
статуса на сайте также сверяет счёт через API, если уведомление потерялось.

Полный возврат обрабатывается общим механизмом возвратов. При частичном возврате
статус сохраняется, администратору отправляется уведомление о ручной сверке
оплаты и баланса. Это также касается случая, когда уведомление об успешной оплате
не дошло до частичного возврата. Автоматическое зачисление или списание по этому
статусу не реализовано. Создание возврата из бота не добавляется.
`authorized`, `partially_captured` и `manual_reconciliation` не считаются полной
оплатой. Тестовые ключи и Sandbox-события не зачисляют реальные средства.

Контракт API: [создание платежа](https://docs.pay.hot/overview/платежи/create-payment),
[получение платежа](https://docs.pay.hot/overview/платежи/get-payment),
[перевыпуск Checkout](https://docs.pay.hot/overview/платежи/reissue-checkout-session),
[подпись и события](https://docs.pay.hot/webhooks).
