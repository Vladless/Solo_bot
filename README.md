<h2 align="center">Автоплатежи PayHOT</h2>

PayHOT поддерживает автопродление картой и через СБП. Для подключения нужны боевой API-ключ, секрет существующего webhook и доступ к рекуррентным платежам у кассы. В разделе настроек касс PayHOT включите карты и/или СБП, затем «Автоплатежи». Параметры срока списания и повторов доступны там же. По умолчанию автоплатежи выключены.

Клиент выбирает способ и подтверждает сумму и период будущих списаний. Привязка подтверждается первой оплатой покупки или продления; при пополнении баланса сохраняется только способ, а автопродление подключается отдельно. Управление доступно в боте и личном кабинете. Подарки, дополнения и пробный период оплачиваются обычными способами PayHOT.

Окончательный результат списания проверяется через API кассы: ответ <code>202</code> означает обработку. Повтор запроса использует тот же ключ и сумму. Отключение автоплатежей останавливает новые отправки; отправленные платежи продолжают сверяться. Удаление способа отзывает разрешение у кассы, а временная ошибка отзыва повторно обрабатывается фоном.

При обновлении добавьте <code>PAYHOT_AUTOPAY = False</code> в локальный <code>settings/config.py</code> и клиентские тексты <code>PAYHOT_AUTOPAY_*</code> в <code>settings/texts.py</code>. Эти файлы поставляются отдельно. Таблицы и защита сохранённых запросов создаются при штатном обновлении схемы БД.

API PayHOT: [первая оплата с привязкой](https://docs.pay.hot/overview/платежи/create-payment), [повторное списание](https://docs.pay.hot/overview/повторные-платежи/create-recurring-charge), [проверка результата](https://docs.pay.hot/overview/повторные-платежи/get-recurring-charge).

<h2 align="center">Каскад через HAProxy</h2>

В установщике нод выберите «Каскад через HAProxy». Сначала установите выход: VLESS TCP Reality, клиентский сквад и IP доверенных входных серверов. Порт выхода по умолчанию — 8443. Затем создайте вход на другом VPS той же панели и выберите готовый выход. Вход использует HAProxy и публикует хост со своим адресом, а параметры Reality и учёт клиентов остаются на выходе.

HAProxy передаёт исходный IP клиента через PROXY protocol v2. Выход принимает этот протокол только с указанных IP; доступ ограничивается собственными правилами nftables даже без дополнения UFW. На входе доступны BBR, fail2ban и UFW. WARP, Psiphon, анти-торрент и правила маршрутизации настраиваются на выходной ноде.

Мастер проверяет SSH, конфигурацию HAProxy, контейнер и клиентский порт, доступность выхода и его профиль в панели. Повтор установки использует сохранённые этапы; при неудачной смене конфигурации восстанавливается прежняя. Удаление входа сохраняет ресурсы выхода. Проверку подключения из клиентской сети выполните после установки.

Основа схемы: [инструкция Solosklad Wiki](https://solo.bbxgate.com/wiki/kaskad-cherez-haproxy-vhod-v-rossii-vyhod-za-granitsey).
