# Дизайн-код пака «Стандарт»: сетка контента в блоке

Правила ниже касаются того, **как расположен контент внутри блока**. Размер самого блока задаёт админ
на сетке страницы, а `useBlockAutoFit` масштабирует содержимое — поэтому в блоках нельзя фиксировать
высоту тела, только высоту рядов и контролов.

## 1. Каркас

- Один блок — одна панель `DefaultPanel`. Своих карточек-обёрток внутри не делаем.
- Шапка панели: заголовок слева, справа **либо** хинт (одна строка, `inkDim`), **либо** одно действие
  (`headerAction`, ссылка-кнопка). И то и другое одновременно — нет.
- Тело — `DefaultBody`: поля `26 / 8 / 18` (бока / от шапки / до низа), шаг между группами `12`.
  Ручных `padding: "..."` в блоках быть не должно.

## 2. Три зоны блока и ничего кроме них

```
┌──────────────────────────────┐
│ шапка: заголовок + хинт/ссылка│  фиксированная высота
├──────────────────────────────┤
│ контент: ряды / список /      │  тянется, начинается сразу под шапкой
│ карточки — на своих местах    │
│                              │
├──────────────────────────────┤
│ футер: кнопка и/или страницы  │  прижат к низу, высота ≥ 44
└──────────────────────────────┘
```

Тело блока (`DefaultBody`) — flex-колонка на всю высоту панели, футер (`DefaultFooter`) — `marginTop: auto`.
Поэтому кнопка и листалка всегда на одной и той же высоте: у низа блока, независимо от того,
сколько строк на странице и есть ли вообще страницы. Пустой футер сохраняет свою высоту —
блок не «дышит» при появлении второй страницы.

## 2.1. Страницы списка не двигают контент

`DefaultListRows`/`DefaultRows` принимают `slots` — сколько строк держать на странице
(обычно `pageSize`). Слоты:

- нумерованы: ключ строки — номер слота, а не id записи, поэтому листание **меняет только текст**
  в уже существующих узлах — нет перемонтирования, нет мигания, нет рефита автоскейла;
- добиваются пустыми: последняя страница с двумя записями занимает столько же места, сколько полная;
- помечены `data-content-stable="true"` — анимация смены контента (`useContentSwitchFade`)
  внутри таких зон не играет: листание страниц не считается сменой содержимого блока.

Отсюда правило: **любой пагинированный список обязан передавать `slots`**, иначе блок начнёт
дёргаться при листании.

## 3. Вертикальный порядок

Сверху вниз всегда одинаково:

1. пояснение (одна строка, `inkDim`) — если нужно;
2. главное значение блока (число/сумма, `font.xl`, `bold`) — если блок про число;
3. контент: ряды, список или карточки-опции;
4. `DefaultFooter` — прижат к низу блока: primary-кнопка и/или пагинация.

Контент прижат к верху, действия — к низу. Пустоту в высоком блоке не «размазываем» по центру:
предсказуемее, когда ряды всегда начинаются на одной высоте.

## 4. Ряды

- «Поле → значение» — `DefaultRow`: высота `44`, метка слева (`font.sm`, `inkDim`),
  значение справа (`font.smPlus`, `bold`, tabular-nums). Разделители рисует `DefaultRows`.
- Длинное значение (больше 28 символов) не сжимает метку и не съезжает: ряд становится
  двухстрочным — метка сверху, значение под ней, левый край общий. Короткие значения остаются
  справа в одной строке.
- Список сущностей — `DefaultListItem` внутри `DefaultListRows`: высота `56`, слева иконка и две строки
  (заголовок `font.smPlus` + мета `font.xs`), справа значение/статус, затем действие.
- Ряд не растёт от кнопки: внутри ряда допустима только chip-кнопка высотой `30` (`CHIP_H`).

## 5. Действия

- Primary-кнопка одна на блок и живёт в `DefaultFooter`, растянутая на всю ширину футера.
- Поле и кнопка — **одна группа**: `<DefaultFooter stack>` держит их вместе колонкой у низа блока
  (поле, статус, кнопка). Разрывать пару «поле сверху, кнопка внизу» нельзя — между ними появляется
  пустая полоса.
- Экран с одним действием (привязка, подтверждение): подпись экрана сверху, действие по центру
  свободного места (`DefaultFocusArea`), «Назад» — в футере.
- Ссылки и «Все записи» — в шапке через `headerAction`.
- В рядах и карточках — только chip-кнопки; текстовых «кнопок» без фона не делаем.
- Пагинация — только `DefaultPagination` в футере.

## 6. Экран-фокус внутри блока

Привязка почты/Telegram, подтверждение, один вопрос — это `DefaultFocusArea`: контент по центру
свободного места, кнопка возврата — в футере во всю ширину. Зона помечена `data-content-stable`,
поэтому обновление данных внутри неё не запускает анимацию и блок не моргает; геометрия блока
не меняется, значит автоскейл не пересчитывает масштаб.

## 7. Пустые состояния

`DefaultEmptyState` — по центру свободного места: одна строка `font.sm`/`inkDim` и максимум одно действие.
Текст пустого состояния всегда редактируемый ключ блока.

## 8. Карточки-опции

Тарифы, подарки, способы оплаты — `DefaultOptionCard`: одинаковая высота в ряду, порядок
«бейдж → заголовок → мета → цена», действие внизу карточки. Сколько карточек в ряд — считает
`useBalancedColumns`; при узкой колонке вместо карточек компактные ряды `DefaultOptionRow`.

## 9. Типографика значений

| Роль | Размер | Вес |
|---|---|---|
| заголовок блока | `font.lg` | bold |
| главное число | `font.xl`+ | bold |
| значение ряда | `font.smPlus` | bold |
| метка ряда | `font.sm` | regular, `inkDim` |
| мета/подпись | `font.xs` | regular, `inkMute` |

Промежуточных размеров не вводим.

## 10. Автоскейл

- Тело не задаёт `height`/`minHeight` больше нужного — иначе `useBlockAutoFit` не сможет измерить
  естественную высоту и начнёт сжимать контент.
- Фиксированы только `ROW_H`, `LIST_ROW_H`, `CHIP_H`, `CONTROL_H` — за счёт этого масштаб предсказуем.
- Прокрутка внутри блока (`DefaultBody scroll`) — только там, где список принципиально длинный;
  в остальных случаях страницы делает пагинация.

## 11. Радиус и подложка карточки

Приоритет один и тот же для всех блоков пака:

1. «Оформление» блока (`vs_radius`, `vs_surface*`) — то, что админ выбрал в редакторе элемента;
   применяет `usePanelDecor()`, поэтому карточка обязана его спредить (`...decor`).
2. Настройка «радиус элементов» в теме — через `var(--block-visual-radius)` на ячейке блока;
   значение считает `packPanelRadiusPx(pack, radiusOption)` (базовый радиус пака × коэффициент,
   `xl` = базовый вид пака, `none` = прямые углы).
3. Числовой `t.radius.md` — только страховка внутри `var(...)`.

Рельс сайдбара по умолчанию без скругления (`vs_radius: "none"`), а его цвет выбирается по одному
правилу: **если светлота шапки совпадает с режимом темы — рельс берёт цвет шапки и стыкуется с ней
без шва; иначе он ведёт себя как карточка и берёт `t.panel`**. У тёмной шапки в тёмной теме сайдбар
продолжает шапку, в светлой — белый и такой же чёткий, как блоки. Палитра сайдбара считается от
выбранного цвета через `defaultThemeOnSurface(t, surface)` — иначе на тёмном рельсе остаётся тёмный
текст. Свой цвет подложки блока (Оформление → подложка) сильнее правила.

Общий слой подложки темы (`theme-paper-surface` внутри `SurfaceEffectFrame`) в паке не рисуется:
он позиционируется абсолютом поверх карточки и подменяет цвет пака цветом токена `surfaceColor`
(именно так у страниц входа и оплаты блок оказывался другого цвета и без скругления). Блок пака
рисует карточку сам — `panelStyle(t)` или свои `background: t.panel` + `borderRadius:
var(--block-visual-radius, …)` — и спредит `usePanelDecor()`. Если блок всё же оборачивается в
`SurfaceEffectFrame` (например ради обводки или hover), он передаёт `surfaceStyle: undefined` и
радиус ячейки в `radiusValue`.

## 12. Мягкая тень — одна на весь пак

Карточки поднимаются тенью `panelShadow(t)` (и `panelShadowSm` для мелких плашек), а поверхности,
которые стыкуются с шапкой или краем экрана — `panelShadowFlush(t)`: та же тень без внутреннего
ободка, иначе inset-линия читается как разделитель на стыке (именно её видно было между шапкой и
сайдбаром). Она включена по умолчанию и выключается флажком «Мягкая тень карточки»
в «Оформлении» блока (`vs_elevation: false`) — тень читает `t.elevation`, поэтому один флажок
гасит её и у карточки, и у сайдбара. Своя тень/свечение из «Тень / свечение» (`vs_glow`)
накладывается поверх и живёт отдельно.

## 13. Узкая ячейка

Блок обязан уметь сужаться: если контент не влезает, он убирает необязательное, а не переносит
строку и не распирает ячейку. Ширину даёт `useContainerWidth()`:

- шапка кабинета масштабирует свои контролы по ширине ячейки (`topbarAutoScale`, границы
  `TOPBAR_SCALE_MIN`/`TOPBAR_SCALE_MAX` от `TOPBAR_DESIGN_WIDTH`). Ниже
  `TOPBAR_SEARCH_MIN_WIDTH` она переносит контент по строкам (поиск слева, иконки справа,
  текстовая кнопка — своей строкой), ниже `STACK_WIDTH` поиск занимает строку целиком, и лишь
  ниже `TOPBAR_SEARCH_HIDE_WIDTH` он убирается совсем. Поэтому размеры контролов внутри неё
  задаются только через `t.px(...)` — фиксированных «44» быть не должно;
- списки-опции ниже своего порога переходят на компактные ряды (`DefaultOptionRow`);
- поле и кнопка встают в столбик (`DefaultFooter stack`).

Пороги живут в `contentTokens.ts`, чтобы их можно было менять в одном месте.

## 14. Движение

Анимации блока живут в трёх слоях, и каждый настраивается в редакторе элемента, вкладка
«Анимации»:

1. **появление блока** — `animationType` (список типов один на весь сайт:
   `landing/blockAnimation/entrance.ts`), триггер, длительность, задержка;
2. **смена контента** — `contentAnimation` (типы в `landing/useContentSwitchFade.ts`); играет
   только вслед за действием клиента и не трогает зоны `data-content-stable`;
3. **отклик на действия внутри блока** — `interactionMotion` (пресеты в
   `landing/blockAnimation/interaction.ts`). Порядок: настройка блока → настройка страницы
   («Анимации» в панели темы, токен `pageMotionDefault`) → характер пака; у «Стандарта» «мягкий».

Блок, закреплённый при прокрутке (`showStaticOnScroll`, например сайдбар кабинета), общий
контейнер появления не получает — трансформация ломала бы закрепление. Такой блок вешает класс
появления на себя сам и снимает его в `onAnimationEnd`, а тип и длительность берёт из тех же
полей вкладки «Анимации» (`animationType`, `animationDuration`). У сайдбара «Стандарта» по
умолчанию стоит «Из-за левого края» — выключается там же, значением «Без анимации».

Третий слой блок не пишет сам: `LandingGrid` ставит на ячейку `data-block-motion`, а
`app/styles/block-motion.css` раздаёт движение по разметке. Блоку остаётся расставить метки:

- `data-motion-stagger` — контейнер, ряды которого проявляются каскадом (уже стоит в
  `DefaultRows` и `DefaultListRows`);
- `data-motion-lift` — строка или карточка, которая поднимается под курсором;
- `data-motion-bar` — заполнение полосы: вырастает при первой отрисовке и тянется при смене данных;
- `data-motion-pulse` — индикатор «живого» состояния (нода онлайн), дышит;
- `data-motion-draw` — линия графика, прочерчивается; на `path` нужен `pathLength={1}`.

Наведение (подъём + подсветка), нажатие и переходы цвета слой берёт на себя сам, размечать их не
нужно; переключатели (`role="switch"`), вкладки (`role="tab"`) и элементы со своим hover-эффектом
(`.btn-hover-wrap`, `.surface-hover-wrap`) он не трогает, а отдельный элемент отказывается
атрибутом `data-motion-skip`. Свой inline-`transition` блока сильнее слоя, поэтому у блоков со
своей анимацией ничего не меняется. Значение «Без отклика» гасит весь третий слой у этого блока,
`prefers-reduced-motion` — у всех.
